# 🚀 Деплой Telegram бота

Ниже — короткий и рабочий вариант деплоя на Railway.

## Railway
1. Залейте репозиторий в GitHub.
2. В Railway создайте проект и выберите **Deploy from GitHub repo**.
3. В Settings → Environment добавьте:
   - `BOT_TOKEN`
   - `ADMIN_USER_ID`
   - (опционально) остальные API ключи из `env.example`
4. Railway сам запустит команду из `Procfile`.

## Локальный запуск
```bash
cp env.example .env
# заполните BOT_TOKEN и ADMIN_USER_ID
pip install -r requirements.txt
python admin_bot.py
```

## Обновление без изменения расписания

Изменения кода не требуют менять `BOT_TOKEN`, `ADMIN_USER_ID`, API-ключи,
сертификат T-Invest или время сводки. Существующий `bot_settings.json`
читается как раньше. Интервал проверки цен, время первого запуска и
регистрация ежедневной задачи сохранены.

Поддерживаются Python 3.9 и Python 3.10+. На Python 3.10+ устанавливается
aiohttp 3.14.3. На Python 3.9 используется совместимая версия 3.13.3 и
Python-парсер HTTP вместо C-расширения — предусмотренный разработчиками
обход CVE-2026-69244. Версии python-telegram-bot и планировщиков сохранены.

Перед обновлением сохраните действующие JSON-файлы состояния из запущенного
сервиса. Копии из Git могут отличаться от актуальных подписок и настроек.
`notifications.json` и `bot_settings.json` в этом исправлении оставлены
без изменений, чтобы не сбросить работающую рассылку.

## Постоянное хранение состояния

По умолчанию пути к файлам остались прежними. Для сохранения состояния между
развёртываниями поддерживается необязательная переменная `DATA_DIR`, например
`/data`, указывающая на подключённый Railway Volume. Один каталог должен
использоваться только одним экземпляром бота.

В этом каталоге хранятся:

- `notifications.json` — подписки и пороги;
- `bot_settings.json` — время и часовой пояс сводки;
- `price_history.json` — история для отображения дельт;
- `alert_state.json` — отдельная история проверок и очередь недоставленных алертов;
- `last_known_rates.json` — последние реальные курсы с исходным временем;
- `user_data.json` — данные профиля.

При первом включении `DATA_DIR` бот копирует найденные локальные JSON-файлы
в новый каталог. Уже существующие файлы в каталоге не перезаписываются,
исходные файлы не удаляются. Для переноса актуального состояния сначала
поместите резервную копию **из работающего сервиса** на постоянный диск:
автоматический перенос из нового checkout не восстановит потерянные
изменения старого контейнера.

Подключение volume, перенос данных на Railway и удаление исторических
рабочих JSON из Git в рамках исправления не выполнялись. Убирать эти файлы
из индекса следует после проверки постоянного хранилища и сохранности
действующей подписки. [Файлы Railway вне volume не сохраняются между
развёртываниями](https://docs.railway.com/services).

## Проверка изменений

```bash
BOT_TOKEN=000000000:TESTTOKEN ADMIN_USER_ID=1 TINVEST_API_TOKEN='' \
  python -m unittest discover -s tests -v
python -m pip check
```

Тесты используют временное хранилище и подменяют отправку сообщений/API.
Они не запускают polling, не рассылают сводки и не меняют рабочие JSON.
После неопределённого результата Telegram (например, сетевого таймаута)
повторная доставка алерта может дать дубликат: повтор имеет тот же ID
события. Пропуск уведомления из-за такого сбоя больше не считается успешной
доставкой.
